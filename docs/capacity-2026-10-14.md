# A15: проверка ресурсов на x86-64 — 2026-10-14

Рекомендация для рассмотрения владельцем: **2 vCPU, 4 ГиБ RAM и Celery concurrency=1**
для согласованной стартовой нагрузки, описанной ниже. Предлагаемый профиль прошёл
обе трёхминутные нагрузочные фазы, одновременное выполнение миграции и операций
сохранения данных, а также пересоздание контейнеров. Запас памяти в каждом
контейнере приложения составил не менее 15%. Это рекомендация по планированию
памяти, а не гарантия задержек на Azure VM или разрешение изменить размер production VM.
Измерения и рекомендации A15 готовы к ревью; применение в production остаётся
отдельным решением владельца.

## Границы проверки и воспроизводимые входные данные

Владелец согласовал стартовую нагрузку: четыре одновременных читателя каталога,
два загрузчика файлов, изображения 4K и видео 1080p. Тестовые данные: 100
синтетических игр, RGB PNG 3840×2160 (20.2 МиБ), пятисекундное видео H.264
1080p/24 кадра в секунду (7.7 МиБ) и 16 МиБ данных Redis. Каждая фаза mixed/deploy
длится 180 секунд. Клиенты отправляют следующий запрос после завершения предыдущего;
между запросами читателя задана пауза 200 мс. Все принятые видео должны быть обработаны.

Хост: Arch Linux, Ryzen 7 PRO 4750U, 13.4 ГиБ RAM, Docker 29.8.1, Compose 5.5.1,
cgroup v2/systemd. Контейнеры приложения и миграции используют CPU `0,2` — два
физических ядра; квоты CPU отдельных сервисов сохраняются. Генераторы нагрузки
и Azurite не ограничены этим набором CPU и исключены из суммы памяти приложения.
Они и существующие сервисы хоста могут конкурировать за выбранные ядра.
Сервисы хоста продолжали работать, поэтому показатели RAM/PSI/swap включают
постороннюю активность.

Образы приложений и пограничного прокси загружены по неизменяемым digest для
linux/amd64 из последних успешных запусков deployment, перечисленных ниже.
Исходники не пересобирались, production-данные и секреты не копировались.
Таким образом определены артефакты, развёрнутые через CI; новая проверка
production или нагрузочный тест на нём не выполнялись.

## Одновременное потребление памяти приложением

| Фаза | Рабочий объём памяти базового профиля | Рабочий объём памяти предлагаемого профиля | memory.current предлагаемого профиля |
| --- | ---: | ---: | ---: |
| Простой — idle | 349.9 МиБ | 300.1 МиБ | 348.0 МиБ |
| Смешанная нагрузка — mixed | 1055.9 МиБ | 1247.2 МиБ | 1365.1 МиБ |
| Развёртывание — deploy | 1355.5 МиБ | 1320.3 МиБ | 1449.6 МиБ |
| После завершения задач — cooldown | 1263.2 МиБ | 1254.8 МиБ | 1303.3 МиБ |
| Пересоздание — recreate | 1249.3 МиБ | 1241.4 МиБ | 1289.9 МиБ |

Это суммы, измеренные в один момент времени для контейнеров приложения, данных,
пограничного прокси и временного контейнера миграции. При расчёте рабочего объёма
памяти вычитается неактивный файловый кеш; memory.current включает этот кеш и
используется ниже для консервативного бюджета. Суммы RSS повторно учитывают общие
страницы памяти и служат диагностическим показателем. Периодические замеры могут
пропустить короткие пики; пики, зарегистрированные ядром для каждого контейнера,
проверяются отдельно.

Лимиты в candidate.json остаются тестовыми параметрами; production Compose не
менялся. Оба профиля завершили работу без OOM и неожиданных рестартов, но только
предлагаемый профиль прошёл заданную проверку запаса.

Все записанные HTTP-ответы имели код 200; необработанных принятых видео не осталось.
Счётчики описывают одно сравнение клиентов, ожидающих ответа перед следующим
запросом, и не доказывают статистически значимого улучшения производительности.
Concurrency=1 выбран ради запаса памяти; результаты не подтверждают дополнительной
пропускной способности от двух worker-процессов. Обработка больших изображений
занимает несколько секунд, что отражается в p95.

Памяти хоста с 1 ГиБ недостаточно уже для измеренной потребности приложения,
ещё до учёта ОС и обслуживания. В качестве стартового бюджета для рассмотрения
рекомендуются 4 ГиБ; 2 ГиБ не сохраняют перечисленные резервы. Нельзя определять
RAM виртуальной машины сложением потолков контейнеров. Общий лимит 4 ГиБ на
ThinkPad не устанавливался: этот бюджет выведен из измеренной потребности и
указанных резервов, а не подтверждён отдельным тестом VM с 4 ГиБ.

Регион production не подтверждён; это не индивидуальное предложение для подписки.

Перед применением нужно проверить доступность SKU, условия CPU-кредитов,
фактический регион и стоимость. Облачные ресурсы и платные сервисы не создавались.

## Покрытие, ограничения и проверки

Согласованная владельцем стартовая нагрузка позволяет использовать эти результаты
для ограниченной рекомендации по ресурсам. Более крупные каталоги и медиа,
длительная нагрузка, ресурсоёмкие будущие миграции данных и особенности облачной
производительности требуют новой проверки. Alembic уже находился на head.
Во время снимка и миграции API намеренно оставался запущенным; production
предварительно останавливает API. Пересоздание выполнялось после завершения
запросов. Измерялся дополнительный расход памяти, а не развёртывание без простоя
или восстановление резервной копии. Production-приложение, схема, лимиты и
доступы не менялись.

Предыдущая попытка x86-baseline-1 завершилась до нагрузки: root без возможности
обходить файловые права не смог записать результаты в закрытый каталог хоста.
Теперь probe и collector используют UID/GID пользователя, запустившего стенд;
для этого поведения Linux добавлен регрессионный тест. Неудачная подготовительная
попытка исключена из доказательств успешных измерений.

Прошли 127 модульных тестов. Нативные x86-прогоны базового и предлагаемого профилей
прошли проверку полноты измерений; предлагаемый профиль также прошёл проверку запаса.
Проверки Nginx frontend/admin с `--add-host backend:127.0.0.1` прошли.
Конфигурация Compose и diff прошли проверки. API-запросы выполнялись через
фактические образы пограничного прокси, витрины и админ-панели.
